# Работа над ParcelQuote

Это учебный QA-проект. Продукт, тесты и документация используют русский язык;
идентификаторы кода на английском. Тарифы и расстояния вымышленные.

## Проверки перед pull request

Нужен Docker с Linux-контейнерами и Docker Compose. Все автоматизированные
проверки запускаются в сервисе `tests`, включая отдельные и отладочные прогоны.

```sh
docker compose --profile test run --build --rm tests
```

Команда проверяет ESLint, TypeScript, unit, внутренние интеграционные, HTTP API
и UI. Быстрые проверки без приложения:

```sh
docker compose --profile test run --build --rm --no-deps tests npm run check
```

Просмотр отчётов и команды для отдельных наборов описаны в [руководстве запуска](docs/development.md).
При изменении исходников или зависимостей пересобирайте тестовый образ.

## Изменения тестов

- Сначала определите требование и ожидаемый результат независимо от кода продукта.
- Для исправления дефекта покажите падающую проверку до исправления и успешную после.
- Независимые входные данные оформляйте отдельными `test` на уровне модуля.
  Связанный сценарий отказа и восстановления может оставаться одним тестом.
- Имена должны различаться словами, а не только знаками: «пустой объект» и
  «пустой массив», «через точку» и «через запятую». Playwright очищает знаки
  в именах каталогов артефактов, что может вызвать коллизии.
- Используйте роли и подписи полей, web-first assertions и свежие контексты.
  Фиксированные паузы, force-клики, `page.pause()` и ElementHandle запрещены.
- Для Playwright задавайте фичу и историю через `reportScenario` из `tests/report.ts`.
  Именованные шаги Allure описывают действие и ожидаемый результат на русском.
- Обновляйте [матрицу покрытия](docs/qa-coverage-matrix.md), если покрытие изменилось.
  Не увеличивайте число тестов ради метрики и не скрывайте ошибки через retry или skip.

## Pull request

Опишите проблему, итоговое поведение и выполненные проверки. Для ошибки приложите
воспроизводимые шаги; для интерфейса полезен скриншот. Укажите непроверенные области.
Один PR решает одну задачу. Для изменения поведения обновите соответствующий контракт
в [правилах продукта и API](docs/product-contract.md).

В репозиторий входят исходники и lockfile. Зависимости, отчёты, traces, локальные
скиллы и файлы окружения в коммиты не включаются. Инженерные задачи агента пока
ведутся локально по [правилам трекера](docs/agents/issue-tracker.md).
