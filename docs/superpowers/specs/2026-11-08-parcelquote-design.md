# ParcelQuote — описание первой версии

Статус: утверждено пользователем 2026-11-08.

## Цель

Небольшой сервис расчёта доставки для GitHub-портфолио QA Automation Engineer.
Сначала создаётся работающий продукт с явными правилами, затем отдельным этапом —
автотесты на TypeScript и Playwright, CI/CD и отчётность.
Интерфейс, сообщения об ошибках и README — на русском.
Названия полей API и идентификаторы кода — на английском.

## Объём

- Одно приложение: JSON API и одна веб-страница.
- Обычная и экспресс-доставка, опция хрупкого груза.
- Подробное объяснение стоимости.
- Без базы данных, аккаунтов, истории и внешних сервисов.
- Тарифы в локальном конфигурационном файле, изменения требуют перезапуска.
- Каждый запрос независим, пользовательские данные между запросами не сохраняются.
- Тарифы учебные, не являются предложением реального перевозчика.

Регистрация, оплата, адреса, карты, отслеживание посылок, админка и микросервисы
в первую версию не входят. Расширенная тестовая инфраструктура и деплой — позже.
Основной риск проекта — разрастание реализации в ущерб демонстрации QA-навыков.

## Рассмотренные подходы

1. Python + FastAPI: небольшой API, но новый для пользователя язык. Отклонён.
2. Node.js + TypeScript + Fastify: выбран с учётом стека пользователя.
   Один язык для бэкенда и будущих тестов; входные данные проверяются схемами.
3. Для страницы выбран обычный HTML/CSS/JavaScript вместо отдельного SPA:
   достаточно одной формы, результат и ошибки можно проверять Playwright.

Отдельный фронтенд-фреймворк и система хранения не нужны для согласованного объёма.

## Входные данные

Все поля обязательны. Неизвестные поля отклоняются.

| Поле API | Смысл | Допустимые значения |
|---|---|---|
| weightKg | Фактический вес | JSON-число от 0.1 до 30, шаг 0.01 кг |
| lengthCm | Длина | Целое JSON-число от 1 до 100 |
| widthCm | Ширина | Целое JSON-число от 1 до 100 |
| heightCm | Высота | Целое JSON-число от 1 до 100 |
| distanceKm | Расстояние | Целое JSON-число от 1 до 3000 |
| deliveryType | Тип доставки | Строка standard или express |
| fragile | Хрупкий груз | JSON boolean |

Границы включены. Строки вместо чисел, null, неверные типы и значения
отклоняются без автоматического исправления. Ограничение 30 кг относится только
к фактическому весу; объёмный вес может быть больше.
Шаг 0.01 относится к числовому значению, а не записи: 1.250 эквивалентно 1.25.

## Правила расчёта

1. Объёмный вес = lengthCm × widthCm × heightCm / 5000 кг.
2. Расчётный вес = max(фактический вес, объёмный вес).
3. Оплачиваемый вес = округление расчётного веса вверх до целого кг.
4. Оплачиваемые блоки расстояния = округление distanceKm / 10 вверх.
5. Базовый сбор = 100 ₽.
6. Стоимость веса = оплачиваемый вес × 50 ₽.
7. Стоимость расстояния = оплачиваемые блоки расстояния × 10 ₽.
8. Промежуточная сумма = базовый сбор + стоимость веса + стоимость расстояния.
9. Множитель доставки: standard — 1; express — 1.5.
10. Доплата за экспресс = промежуточная сумма × (множитель − 1).
11. Доплата за хрупкий груз = 100 ₽ при fragile=true, иначе 0 ₽.
12. Итог = промежуточная сумма + доплата за экспресс + доплата за хрупкий груз.

Объёмный и расчётный вес перед округлением вверх не округляются.
При текущих тарифах все денежные результаты — целые рубли; дополнительное
округление цены не требуется. Будущая смена тарифов на дробные потребует
отдельного решения о денежной точности.

Примеры для 2 кг, 10 × 10 × 10 см, 15 км:

- standard, не хрупкий: 100 + 100 + 20 = 220 ₽.
- express, не хрупкий: 220 × 1.5 = 330 ₽.
- express, хрупкий: 330 + 100 = 430 ₽.

## API

POST /api/quote, Content-Type: application/json.

Успех: HTTP 200, JSON с полями:

- actualWeightKg, volumetricWeightKg, chargeableWeightKg, billedWeightKg;
- distanceBlocks;
- baseCostRub, weightCostRub, distanceCostRub, subtotalRub;
- deliveryMultiplier, expressSurchargeRub, fragileSurchargeRub;
- totalRub, currency (RUB).

Невалидные данные, неизвестные/пропущенные поля и некорректный JSON:
HTTP 400, единая форма ответа:

```json
{"errors":[{"field":"weightKg","message":"Вес должен быть от 0,1 до 30 кг"}]}
```

Для ошибки всего тела field=null. По возможности возвращаются ошибки всех полей;
порядок ошибок не является частью контракта. Неизвестное поле указывается своим
именем. Случайный внутренний сбой возвращает HTTP 500 с общим сообщением на русском,
без стека и внутренних деталей. Неверный Content-Type возвращает HTTP 415 в той же
форме ошибок. Проверка на сервере обязательна независимо от браузерных проверок.

## Веб-страница

- Русские названия и единицы измерения всех полей, radio/select для типа доставки,
  checkbox для хрупкого груза, кнопка «Рассчитать».
- Начальные значения: числовые поля пусты, тип standard, fragile=false.
- Вес принимает одну запятую или точку как десятичный разделитель; перед запросом
  форма преобразует значение в число. Пустое поле не превращается в ноль.
- Ошибки рядом с полями, введённые значения сохраняются.
- Результат показывает три вида веса, оплачиваемые килограммы и блоки расстояния,
  составляющие цены и итог в рублях. Для express показана отдельная доплата.
- Изменение любого параметра убирает предыдущий результат.
- Во время запроса повторная отправка блокируется. Ответ для параметров,
  изменённых после отправки, не показывается как актуальный расчёт.
- Сетевой сбой показывает общее сообщение и позволяет повторить запрос.
- У полей есть связанные label, форма доступна с клавиатуры;
  результат и ошибки доступны вспомогательным технологиям.
- Сервис и страница обслуживаются одним приложением с одного origin.

## Готовность первой версии

- Проект устанавливается и запускается локально по инструкции README.
- Страница вызывает реальное API, расчёт выполняется на сервере.
- Примеры дают 220, 330 и 430 ₽; ограничения выполняются на уровне API.
- Показаны ошибки, разбивка цены и сброс результата после изменения параметров.
- Есть минимальная проверка основной формулы и валидации для надёжности реализации.
  Расширенное портфолио автотестов остаётся отдельным следующим этапом.
- README объясняет запуск, правила, примеры запросов и учебный характер тарифов.

## Решения, предложенные автором для проверки пользователем

Имена полей и конкретная форма ответов API, HTTP 415/500, расположение тарифов,
начальные значения формы, защита от устаревшего ответа и минимальные проверки
при реализации — уточнения автора, а не отдельные ранее согласованные решения.
